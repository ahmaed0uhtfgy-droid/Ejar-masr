# إزاي ترفع التحديث (من غير terminal) وليه كل خطوة

## الفكرة في سطرين
الموقع بيتنشر لوحده من GitHub عبر Cloudflare. هترفع الملفات المتغيّرة على GitHub ← Cloudflare يبني وينشر ← تتأكد ← (اختياري) تحدّث قواعد Firestore. كل خطوة ليها طريق رجوع في دقيقة.

## 0) قبل أي حاجة (دقيقتين) — ليه: عشان ترجع لو حصل أي شيء
1. GitHub ← الـ repo ← زر **Code** ← **Download ZIP** واحفظه (ده نسخة احتياطية من الكود الحالي).
2. Firebase Console ← Firestore ← **Rules**: انسخ القواعد الحالية في ملف نصي (لكن مش هنغيّرها في الخطوة 1).

## 1) ارفع الكود — على 3 دفعات (GitHub بيقبل 100 ملف في الرفعة)
عندك 3 ملفات مضغوطة، **بالترتيب**:
1. **`update-1-app.zip`**: الواجهة والصور والإعدادات (فولدرات `src` و`public` وملفات الجذر).
2. **`update-2-functions.zip`**: السيرفر (فولدر `functions`). **مع الأول، ده اللي بيغيّر سلوك الموقع.** ارفعهم الاتنين قبل ما تستنى نشر Cloudflare.
3. **`update-3-tests-docs.zip`**: الاختبارات والتوثيق والـ CI. مفيهوش أي تأثير على الموقع.

لكل واحد:
1. فك الضغط على جهازك.
2. GitHub ← الـ repo ← **Add file** ← **Upload files**.
3. اسحب **محتويات** المجلد المفكوك (مش المجلد نفسه). لازم تشوف الفولدرات وملفات زي `package.json`. (لو `.github` مخفي على جهازك فعّل "إظهار الملفات المخفية".)
4. استنى لحد ما كل الملفات تظهر، واكتب رسالة مثل `Update: SEO, security, map, compare, dark mode` واترك **Commit directly to the main branch** ثم **Commit changes**.

**ليه:** كل التغييرات إضافة أو تعديل، فمفيش حاجة هتتمسح. كل رفعة بتشغّل نشر Cloudflare، فلو رفعت 1 لوحدها هيتنشر نشر جزئي ثم يتصلح بعد الرفعة التانية (مش مشكلة، لكن الأفضل ترفعهم ورا بعض).

**ملف واحد اتشال:** `public/robots.txt` (اتحوّل لدالة بتتبع دومينك). مش لازم تمسحه.

**نظام المقالات الآلي:** الكود الموجود منه **غير مفعّل ومش ظاهر على الموقع** (مفيش مسار ولا واجهة له بعد). التفاصيل في `docs/ARTICLES-STATUS.md`.

## 2) راقب النشر (3–5 دقايق)
Cloudflare ← Workers & Pages ← مشروعك ← **Deployments**: لازم النشر الجديد يبقى **Success**.
- لو **Failed**: الموقع القديم لسه شغال (مفيش أي أثر على الزوار). افتح الـ build log وابعتلي آخر 30 سطر.
- **ليه آمن:** رجّعت `package.json` لنفس الاعتماديات الأصلية، فـ `package-lock.json` لسه متطابق ومش هيفشل التثبيت. وبناء الإنتاج مابقاش يفحص ملفات الاختبارات.

## 3) تأكد إن كل حاجة شغالة (5 دقايق)
افتح الموقع **في نافذة خفية** ثم F12 ← **Network**، وحدّث الصفحة:
1. الصفحة الرئيسية بتفتح وبتعرض الإعلانات ✔
2. في Network لازم تشوف **`/api/settings`** و **`/api/units?...`** بحالة **200** ✔
3. جرّب بحث بمحافظة، وبترتيب السعر، واضغط "عرض المزيد" ✔ (لازم ما تتكررش إعلانات)
4. افتح إعلان، سجّل دخول، اكشف رقم تليفون ✔
5. افتح `https://موقعك/robots.txt` و`/sitemap.xml`: لازم يفتحوا وفيهم رابط موقعك.
6. **الواجهة الجديدة:** فعّل الوضع الليلي (لازم يبقى أسود/رمادي غامق مش أزرق)، وجرّب زرار "قارن" على إعلانين ثم اضغطه تاني (لازم يشيل) وافتح صفحة المقارنة واضغط "مسح الكل". وافتح صفحة بحث بالخريطة: الأسعار المتداخلة بتتجمّع في فقاعة بتتفتح بالتكبير، والضغط على سعر بيفتح معاينة الإعلان.
7. في "إضافة إعلان": اسحب الدبوس، جرّب البحث بعنوان، وزرار "موقعي" (المتصفح هيطلب إذن الموقع).
8. انشر إعلان تجريبي ← لازم يظهر في صفحتك فورًا، وفي البحث خلال حوالي 10 دقايق (ده تأخير مقصود لتوفير الحصة) ✔

لو شفت `/api/units` بحالة 500: افتح الرابط في تاب جديد وابعتلي الرد. **الموقع هيفضل شغال** لأن المتصفح بيرجع يقرأ من Firestore مباشرة تلقائيًا، بس من غير التوفير.

## 4) (اختياري، بعد ما الخطوة 3 تنجح) قواعد Firestore الجديدة
بتمنع تسجيل حساب بإيميل شخص تاني وبتحدّد قيمة التأمين. **ما اتجربتش على Firestore حقيقي**، فاعملها بحذر:
1. Firebase Console ← Firestore ← **Rules** ← الصق محتوى `firestore.rules` من المشروع ← **Publish**.
2. فورًا: افتح نافذة خفية وسجّل حساب جديد بإيميل وكلمة سر، وجرّب تسجيل دخول جوجل.
3. لو التسجيل فشل بـ "permission denied": Rules ← **History** (أو القواعد القديمة اللي حفظتها) ← ارجع للنسخة السابقة وابعتلي الخطأ.

## 5) الفهارس — **مش لازم دلوقتي**
نظام البحث الجديد بيستخدم الفهرس اللي عندك أصلًا (`status + createdAt`)، فمش محتاج الـ 9 فهارس الناقصة طول ما الإعلانات النشطة أقل من 300. لما تعدّي 300 هتحتاجهم (اللقطة بتتحوّل لاستعلامات حقيقية). وقتها: Firestore ← Indexes ← Add index لكل صف في `firestore.indexes.json`.

## 6) خطوات الأمان (لما تحب، كل واحدة مستقلة)
اتبع `docs/QUOTA-AND-SPEED.md`: قاعدة Rate limiting + Bot Fight Mode في Cloudflare (5 دقايق)، ثم Firebase App Check (يحتاج تجربة يوم قبل التفعيل).

## 7) رسائل GitHub الحمراء ❌
بعد الرفع هيشتغل CI تلقائيًا (إيميل أو علامة ❌ جنب الـ commit). **ده مش بيأثر على الموقع.** الاختبارات اللي ما قدرتش أشغّلها (قواعد Firestore و Playwright) متعلّمة "informational". ابعتلي نتيجة الـ job الفاشل وأصلّحه. ما تفعّلش `ENABLE_ACTIONS_DEPLOY` قبل ما كلها تبقى خضرا.

## لو حصلت مشكلة في الموقع بعد النشر
Cloudflare ← Deployments ← اختار آخر نشر كان شغال ← **⋯** ← **Rollback to this deployment**. (دقيقة واحدة، بدون أي كود.)
