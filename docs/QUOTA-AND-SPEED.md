# السرعة وحماية الحصص المجانية (Cloudflare + Firebase)

## إيش اتغيّر في الكود
**القلب: لقطة واحدة للإعلانات النشطة.** السيرفر بيقرأ أحدث 300 إعلان نشط **مرة كل 5 دقايق أو أكتر** (بيزيد الفاصل لما الإعلانات تكتر عشان التكلفة تفضل تحت ~12,000 قراءة/يوم)، وبيخزّنها في وثيقة واحدة للسيرفر بس (`publicCache/listings`). كل بحث (محافظة، نوع إيجار، ترتيب بالسعر، "عرض المزيد") بيتجاوب من الذاكرة.
> **التكلفة = عدد الإعلانات ÷ فاصل التحديث. مش بتتعلق بعدد الزوار ولا بتنوّع البحث.** ومش محتاجة فهارس جديدة.

| قبل | بعد | الأثر |
|---|---|---|
| كل زائر يقرأ الإعدادات (2 قراءة) | `/api/settings` (كاش 10 دقايق) + `localStorage` 15 دقيقة | ~0 قراءة لمعظم الزوار |
| كل بحث 12–72 قراءة، وبعض البحوث 200 (الفهارس ناقصة) | اللقطة المشتركة | ~0 قراءة لكل بحث |
| صفحة الإعلان (SEO) تقرأ في كل زيارة | كاش 5 دقايق | قراءة واحدة/إعلان/5 دقايق |
| كل مشاهدة = قراءة + كتابة + طلب | المتصفح بيتخطى لو اتعدّت من أقل من 6 ساعات + تجميع الكتابات (5 مشاهدات = كتابة) + كاش مشترك للتحقق | كتابات أقل 5× |
| `/api/view` ممكن يتضرب بإعلانات مختلفة | 60 طلب/ساعة لكل IP | استنزاف صعب |
| `sign-upload` بدون حد | 40/ساعة/حساب | حماية Cloudinary |
| أي حساب مسجّل يضرب الـ API | 120 طلب/10 دقايق لكل حساب (على الـ edge، قبل أي قراءة) | استنزاف بحسابات مجانية صعب |
| حساب جديد يكشف 20 رقم | أول 24 ساعة: 8 | بيصعّب سحب الأرقام |

**أمان التجربة:** لو الـ API فشل (مهلة 4 ثواني، خطأ، تشغيل محلي) المتصفح يرجع **تلقائيًا** يقرأ Firestore مباشرة ويوقف الـ API دقيقتين.

## تقدير السعة (من الكود، مش قياس حقيقي)
| | قبل | بعد |
|---|---|---|
| قراءات/زائر | ~25–40 (وحتى 200 لبعض البحوث) | ~1–3 (تفاصيل الإعلان) |
| زوار/يوم قبل أول حد | ~1,200–2,000 | ~12,000–16,000 (الحاجز بقى طلبات Cloudflare Functions: 100 ألف/يوم) |
| قراءات الإعلانات نفسها | تتضاعف مع الزوار | ثابتة: ~100 إعلان ≈ 12 ألف/يوم كحد أقصى، 30 إعلان ≈ 8 آلاف |

## لازم تعمله إنت (مفيش طريقة أعمله من الكود)

### 1) الفهارس: مش لازم دلوقتي
النظام الجديد بيستخدم الفهرس اللي عندك (`status + createdAt`). هتحتاج باقي فهارس `firestore.indexes.json` لما الإعلانات النشطة تعدّي 300.

### 2) تأكد إن التحسينات شغّالة (دقيقتين)
1. افتح الموقع المنشور ← F12 ← Network ← حدّث الصفحة.
2. لازم تشوف `/api/settings` و`/api/units?...` بحالة 200. ما تشوفش طلبات كتير لـ `firestore.googleapis.com` في الصفحة الرئيسية والبحث.
3. لو شفت الـ API بحالة 500: افتح الرابط في تاب جديد وابعتلي الرد. غالبًا فهرس ناقص.
4. Firebase Console ← Firestore ← Usage: القراءات اليومية لازم تنزل بوضوح بعد يوم أو اتنين.

### 3) Cloudflare (مجاني، من اللوحة)
- **Security ← WAF ← Rate limiting rules:** (الخطة المجانية فيها قاعدة واحدة) `URI Path starts with /api/` ← 60 طلب كل 10 ثواني لكل IP ← Block لمدة 10 دقايق.
- **Security ← Bots:** فعّل **Bot Fight Mode**.
- **Security ← WAF ← Custom rules:** (5 مجانية) `URI Path equals /api/pay-webhook` و`Method is not POST` ← Block.
- **Caching ← Configuration:** `Browser Cache TTL` = Respect Existing Headers.
- **Speed ← Optimization:** فعّل Brotli وHTTP/3 وEarly Hints (غالبًا مفعّلين).
- **Analytics & Logs ← Web Analytics:** فعّله (مجاني، من غير كوكيز).
- **Workers & Pages ← مشروعك ← Metrics:** راقب Requests/يوم (الحد 100,000).

### 4) Firebase App Check (مجاني، يمنع السكربتات الخارجية من استنزاف القراءات)
الحماية الوحيدة ضد حد بيكلّم Firestore مباشرة بسكربت (القواعد بتسمح بقراءة الإعلانات للجميع).
1. Firebase Console ← App Check ← سجّل تطبيق الويب بـ **reCAPTCHA v3** وخد الـ Site key.
2. ضيف `VITE_APPCHECK_SITE_KEY=<الـ key>` في Cloudflare Pages ← Variables (وفي GitHub Secrets لو بتنشر من Actions) وانشر.
3. استنى يوم وشوف App Check ← Metrics: لازم تشوف طلباتك "Verified".
4. **بعد كده بس** اضغط **Enforce** على Cloud Firestore. (لو فعّلته قبل ما تتأكد، الموقع كله يقف.)
الزائر مش بيحس بحاجة (reCAPTCHA v3 غير مرئي). طلبات السيرفر (Functions) مش متأثرة.

### 5) راقب الحصة
- Firebase Console ← Usage and billing ← Firestore: ضيف تذكير لنفسك لما القراءات توصل 60%.
- **UptimeRobot** (مجاني) على `https://موقعك/api/health` كل 5 دقايق.
- لو قربت من الحدود فعليًا: Blaze plan بيدّيك نفس الحصة المجانية وبتدفع بس على الزيادة (حط تنبيه ميزانية، لكنه مش حد صارم).

## حدود لازم تعرفها
- الحد المعدّل (Rate limit) في الكود لكل مركز بيانات Cloudflare، مش عالمي: مهاجم موزّع على كذا مركز ياخد أكتر. قاعدة الـ WAF فوق + App Check هم اللي بيقفلوا الباب فعلًا.
- نتائج البحث ممكن تتأخر لحد ~10 دقايق عن الحقيقة (إعلان جديد/اتعدّل/اتخفى). لوحة صاحب الإعلان وصفحة الإعلان نفسها طازجة.
- لو الإعلانات النشطة عدّت 300 بيتحول البحث لاستعلامات حقيقية (محتاجة باقي الفهارس) وتزيد القراءات مع تنوّع البحث.
- عدّاد المشاهدات في لوحة المالك ممكن يتأخر لحد 4 مشاهدات.
- لو الإعلانات عدّت ~500 عقد نشط، الـ sweep بيطبع تحذير `truncated` (وقتها وقت الترقية).
