# تجربة الدفع بمفاتيح Paymob الاختبارية (15 دقيقة، أهم تجربة قبل الإطلاق)

**ليه:** كل حماية الدفع بتفترض إن رقم الأوردر في رد Paymob هو نفس رقم الأوردر في الـ callback. الاختبارات اللي عندي بتثبت المنطق، لكن بس دفعة حقيقية تثبت إن Paymob فعلًا بيشتغل بالشكل ده.

## الخطوات
1. في Cloudflare ضع مفاتيح **Test** من Paymob (`PAYMOB_SECRET_KEY`, `PAYMOB_PUBLIC_KEY`, `PAYMOB_INTEGRATION_IDS`, `PAYMOB_HMAC_SECRET`) وانشر. وفي Paymob اضبط Transaction processed callback على `https://دومينك/api/pay-webhook`.
2. ادخل كأدمن ← لوحة المدفوعات ← تبويب الـ sweep ← **فحص اتصال Paymob**. لازم كل السطور ✅ وتشوف "order id: ...".
3. بحساب مالك وحساب مستأجر (نافذتين مختلفتين): انشر إعلان ← المستأجر يطلب الإيجار ← المالك يقبل ← الاتنين يأكدوا العقد ← المستأجر يدفع بكارت اختبار من Paymob.
4. بعد الدفع: القسط لازم يتحول لـ **مدفوع** خلال ثواني (صفحة "إيجاراتي"). 
5. لو القسط فضل "قيد المعالجة" بعد دقيقة:
   - Firebase Console ← Firestore ← collection **`unmatchedCallbacks`**: لو فيه مستند يبقى Paymob بعت الدفع برقم أوردر مختلف عن اللي سجّلناه. ابعتلي محتواه (`orderId` و`knownOrders`) وأعدّل المطابقة.
   - لو مفيش، تأكد من رابط الـ callback في Paymob وإن `PAYMOB_HMAC_SECRET` صحيح (Cloudflare ← Workers & Pages ← Logs).
6. جرّب كمان: اضغط "ادفع" مرتين بسرعة، لازم يفتح نفس صفحة الدفع.
7. تجربة السباق: افتح تابين بحساب المالك، قبّل طلبين على نفس الوحدة في نفس اللحظة. واحد بس لازم ينجح والتاني يظهر "حصل تغيير في نفس اللحظة".
